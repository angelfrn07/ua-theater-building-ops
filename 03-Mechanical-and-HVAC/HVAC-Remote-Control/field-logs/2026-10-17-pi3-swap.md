# 2026-10-17: Pi 4 replaced with a Pi 3 Model B

Done on site by Johnny with Claude, from Johnny's Mac on "Power Church Admin".

## Why
The Pi 4's 8 GB SD card was ~91% full and it was the only copy of the setup. A Pi 3 Model B
was built on 2026-10-16 from `pi-bms-bridge/deploy/` (fresh 32 GB card) as the replacement.

## What we did
1. Powered the Pi 3 at the church with the panel cable unplugged. It joined "Power Church Admin"
   by DHCP at **192.168.1.94** (MAC b8:27:eb:e8:7a:14).
2. Checked `desired.json` / `schedule.json` against the live Pi 4. The md5 sums matched, so nothing needed copying.
3. `sudo poweroff` on the Pi 4, moved the panel cable to the Pi 3's eth0.
4. Verified on the Pi 3:
   - eth0 192.168.1.51, `ip route get 192.168.1.123` -> dev eth0, panel pings at about 0.5 ms
   - `/api/rooms`: 26 units, 11 talking (same as before the swap; the 15 down RTUs are a
     separate, pre-existing issue)
   - Tailscale up as 100.117.82.57 (same identity as before)
   - cf-hvac quick tunnel serving (returns 200 with login). The URL changed, so ask Angel for the current one.
5. `systemctl enable tailscaled`, `disable tailscale-when-live`. The gate only existed to keep
   the cloned Tailscale identity off the network while the Pi 4 was still live.

## Changed addresses
- wlan0 is now **192.168.1.94** (was .88). Tailscale IP, hostname, eth0 .51, and logins are unchanged.
- The old Pi 4 is powered off. Its card is a labeled spare: do NOT power it on while the Pi 3 is live,
  because both use the same Tailscale identity.
